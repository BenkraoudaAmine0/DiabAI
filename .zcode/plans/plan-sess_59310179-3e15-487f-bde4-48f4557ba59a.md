# DiabAI — Final Implementation Plan

## Confirmed decisions
- **Frontend:** Next.js (App Router) + TypeScript + Tailwind CSS, English/French toggle
- **Backend:** Python FastAPI
- **Infra — Supabase only:** Auth · Postgres + pgvector · Storage (scan images, SHAP explanation PNGs, KB docs)
- **LLM:** Gemini only (`GEMINI_MODEL=gemini-3.5-flash-lite` env-driven, no fallback); embeddings via Gemini embedding model (768-dim) in pgvector
- **Accounts:** open signup (Doctor/Patient toggle) **+ doctor-created patients** — doctor picks per patient: email invite link OR temp password shown once; doctor panel shows ALL records of their patients
- **ML model:** binary (🔴 Diabetic / 🟢 Non-Diabetic), artifacts already trained in `models/` → copied to `backend/models_app/diabetes/`

## Diabetes prediction — exact contract (extracted from your notebooks)
- **Features & order:** `['gender','age','hypertension','heart_disease','smoking_history','bmi','HbA1c_level','blood_glucose_level']` (= `scaler.feature_names_in_`)
- **Encodings (verified from training pipeline — the comments in test_model.ipynb are wrong, I use the real ones):**
  - `gender`: Female→0, Male→1 (form offers only these two)
  - `smoking_history` raw→recategorized→encoded: `never|No Info→non-smoker→1`, `current→current→0`, `ever|former|not current→past_smoker→2` (form offers: Never / No Info / Current / Former)
- **Inference (verbatim from test_model.ipynb):** `scaled = scaler.transform(pd.DataFrame([patient])[FEATURES])` → `prob = float(model.predict_proba(scaled)[0][1])` → `prediction = int(prob >= threshold)` with threshold **0.395** loaded from `xgb_threshold.pkl`
- **Tier via `get_risk_tier(prob, hba1c, glucose)`** — Prediabetic override FIRST (`5.7 ≤ hba1c < 6.5` AND `100 ≤ glucose < 126` → **"Prediabetic ⚠️"**), then `prob < 0.3 Low · < 0.5 Moderate · < 0.75 High · else Critical`
- **Result display (mirrors your notebook output):** probability as `xx.x%`, badge 🔴 Diabetic / 🟢 Non-Diabetic, tier badge (incl. Prediabetic ⚠️), top-3 SHAP factors with signed values and ↑ risk / ↓ risk direction, plus a server-generated **SHAP waterfall PNG** (`base_values=explainer.expected_value, data=scaled[0]`, title "name | Score | Tier") uploaded to Storage and shown in the record — replicating your `results/shap_patient_*.png` exactly
- Record saved to `predictions` (patient_id, doctor_id, raw input, prob, prediction, tier, top_factors jsonb, waterfall storage_path)

## Supabase schema (0001_init.sql)
- `profiles(id→auth.users, role, full_name, dob, sex, phone, created_by)` + signup trigger
- `doctor_patients(doctor_id, patient_id, unique pair)` — panel; links on account creation, "add existing by email", and when a doctor runs a diagnostic
- `predictions`, `scans(user_id, patient_id?, scan_type, storage_path, result jsonb)` — images + waterfalls in bucket `scans/{user_id}/…`
- `chat_sessions`, `chat_messages(sources jsonb)`, `kb_documents`, `kb_chunks(vector 768)` + `match_kb_chunks()` RPC
- **RLS:** patients read own records (incl. doctor-created ones); doctors read records they created OR any record of panel patients; KB read-only for authenticated

## Patient account creation flow
`POST /api/patients` (doctor): `{method: invite|temp_password, email, full_name, dob, sex, phone}` → Supabase Admin API (`invite_user_by_email` or `create_user` with generated 12-char password + `email_confirm=true`); temp password returned ONCE → doctor UI shows it once with copy button; both paths set profile (`created_by`) + panel link. Plus `POST /api/patients/link` (add existing by email), `GET /api/patients`, `GET /api/patients/{id}/records` (merged predictions+scans timeline).

## Vision scans + RAG chat (unchanged from prior plan)
- Drop-in `models_app/{foot,neck,eye}/model.{h5|keras|pt|pth|onnx}` + optional `labels.json` (eye = 5 retinopathy grades); 224×224 preprocess; lazy TF/torch imports, onnxruntime default; missing model → clean 503 so the app runs before you add models
- Chat: embed question → top-k pgvector chunks → Gemini answer with numbered citations; conversations persisted

## Frontend pages (EN/FR toggle, persisted)
- Public: landing, `/login`, `/register` (role toggle)
- Doctor: dashboard (panel stats), `/doctor/patients` (panel + New-patient modal with both credential methods + one-time temp-password reveal + add-existing-by-email), `/doctor/patients/[id]` (profile + full history timeline with SHAP waterfalls), `/doctor/diabetes` (form → result card: %, badges, top factors, waterfall), `/doctor/retina`, `/doctor/scans` (foot/neck for a panel patient)
- Patient: home, `/patient/foot`, `/patient/neck`, `/patient/history` (all own diagnostics incl. doctor's — same result cards)
- Shared: `/chat` (citation chips), `/profile` (incl. change password)
- `@supabase/supabase-js` + `@supabase/ssr` middleware, role guards, API calls carry the Supabase token
